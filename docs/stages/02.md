# Stage 02

Status: ACCEPTED. Stage 01 and Stage 02 user acceptance are recorded here.
User confirmation: “完成了，我们下一步是不是03” on 2026-09-28.
Isaac Sim is excluded from all future delivery by user decision.

Implemented: five procedural boards (street, standard, cruiser, longboard,
downhill), deck–truck–wheel rigid-body hierarchy,
passive inclined truck hinges, four spinning cylinder wheels, named deck/foot/
pivot/wheel anchors, checker floor and separate gallery (solid wedge ramp,
platform, rail). Primitive mass properties are computed by MuJoCo from explicit
geometry and masses; parameters are engineering assumptions, not measurements.
The single parameter source is src/skate_sim/models/board.py.

Verification thresholds: compiled dimensions and wheel centers absolute error
<=1e-6 m; axis alignment <0.1 degree; positive masses/inertias and inertia triangle
inequality; initial contact depth >=-1e-6 m; 500-step finite-state smoke test.
All five styles and gallery pass runs/02_check/result.json. This is an asset
smoke test, not the stage-03 passive dynamics acceptance.

Inspect starts paused. Space resumes/pauses; 1–4 change each wheel position by
0.1 rad while paused (explicit inspection edit, no persistent actuator); V toggles
transparent geometry, J joint axes, R restores nominal. Red wheel markers make
rotation visible. Parameters/hash are printed and included in recording metadata.

Interactive acceptance procedure: start each board style with `--inspect`.
Click-drag the deck, front truck, rear truck, and each wheel in the MuJoCo
viewer. Drag in screen directions that produce +X, -X, +Y and -Y world-force
responses; observe the board translate/tilt and the force arrow. Release the
mouse and confirm `mouse_force_N` returns to zero. This is an external viewer
perturbation, not natural dynamics. Use Space to resume, N/M to advance while
paused, and R to clear the selected pose. `V` shows collision transparency and
`J` shows joints; 1-4 are inspection-only wheel edits.

MuJoCo uses the native viewer. mjlab uses a real white Viser web viewer at the
free URL printed by `play.py`, with the same generated XML and CUDA Warp physics.
Its controls include pause/step/reset, scene visibility, X/Y/Z force sliders,
Release Force and a Board asset dropdown that rebuilds the selected style. The
project passes one shared ViserServer into mjviser, so the terminal should show
one HTTP host only. Changing the asset keeps the same process, browser
connection and port while replacing the Warp simulation and Viser scene. The
asset switch is hot: no `play.py` restart is needed, and the current board
returns to its nominal initial state after the rebuild. It is
a backend viewer, not a renamed CPU simulation.

The passive viewer now synchronizes its mouse perturbation into the backend
`xfrc_applied` path and records it separately from keyboard force. Automatic
asset checks pass after this bridge. Stage-02 asset and window acceptance is
complete. Pinned BFM 29DoF asset/checkpoint source review remains a later
robot-stage item. Full passive truck turning, trajectory and return-to-center
are intentionally Stage 03 acceptance items.

Rendering fixes: the old hidden `deck_collision` inspection box is now fully
transparent, so it does not overlap the segmented deck mesh and produce
z-fighting. Viser uses an ephemeral free port; use the URL printed by the
current process, not a stale `localhost:8080` tab from an earlier process.
