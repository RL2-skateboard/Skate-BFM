## Verification and evidence

The independent reference uses official joint names, defaults, gains, scales
and limits plus a rotation-matrix geometric reference. It checks all 721 fields
over at least 128 nonzero legal states, including mixed rotations, quaternion
sign symmetry, all wrist joints, current/history ordering and reset. Acceptance
tolerances are absolute `1e-5`, relative `1e-4`.

Native checks exercise actual named joint indices, action clipping/scales,
held targets and changing PD torque across ten physics substeps. The delay
case checks that an issued command is fed back to the actor before the delayed
command reaches the actuators. Tracking tests cover short end windows and
the playback sequence `1999 -> 2000 -> 0 -> 0`.

CPU tensor mocks exercise mjlab adapter and partial-reset logic. They are not
CUDA physics evidence. The initial restricted execution environment exposed no
GPU; subsequent full local execution accessed the RTX 4060 Ti. Real CUDA robot
N=1/N=64 and rider N=64 reward runs each completed 30 simulated seconds with
1,500 policy updates per environment in the measured interval. The 128-state
CUDA observation oracle's maximum absolute error was `4.7684e-7`. Evidence is
under `runs/noncontact_completion/`, with final scope in `verification.json`.
This does not certify rider skill or the separate strict dynamics replay gate.

Joint inspection is now implemented at `play.py --controller joint --inspect`.
An explicitly labelled pelvis/world weld supports inspection only. All 29
joints, including wrists, have tested positive/negative target response and
limits. `P/O` switch to free-base pose/policy and remove the inspection fixture.
The robot overlay displays selected joint target/q/dq/torque, body gravity and
angular velocity, mode, update counts and model/checkpoint hashes. `N` advances
one physical substep without policy/history updates; `M` advances one control
step. Robot `F` applies a pelvis pulse, not a nonexistent deck force.

Actual native-window and Viser-service startup were checked. Viser control
callbacks were tested against the real service. Browser use and native UI
operation are disabled by the current Work settings, so the agent did not
perform a clicked window review. The user subsequently completed the reopened
native Stage-05 review and explicitly confirmed acceptance. The agent access
limitation remains recorded in `runs/05_completion/ui_review/`; the user session
record is `runs/05_completion/manual_review_02/`.

Full raw inputs/actions and run statistics are saved in
`runs/05_observation_fix/`. Each measured policy run has 15,000 physics steps,
1,500 real ONNX calls, 30 simulated seconds and no reset during the run:

- Reward `move-ego-0-0`: minimum pelvis height about **0.7827 m**;

All three corrected runs remained finite and did not cross the 0.35 m height
fall threshold. This is a ground observation/controller validation, not a

comparison combines the coordinate and command-feedback fixes; it does not

`runs/05_observation_fix/verification.json` is the consolidated validation

## Reproduce

From the project root in the existing `skate-sim-mjlab` environment:

```bash
python -m unittest discover -s tests -v
python -m skate_sim check --stage 05 --backend mujoco \
  --checkpoint checkpoints/bfm-zero --output runs/05_check
```

The stage check executes numerical/contract checks and a real 30-second reward
rollout; it no longer accepts shape and nonzero action alone. Its output points
to the complete policy record.

The existing single visualization entry remains:

```bash
python play.py --backend mujoco --scene robot --controller policy \
  --policy-task reward --latent-name move-ego-0-0 \
  --checkpoint checkpoints/bfm-zero --duration 30 --record runs/05_reward_review
python play.py --backend mujoco --scene robot --controller policy \
  --policy-task tracking --checkpoint checkpoints/bfm-zero \
  --duration 30 --record runs/05_tracking_review
```

The user completed the requested window review and confirmed Stage 05 acceptance
on 2026-11-02. The joint-direction, perturbation, pause/step, reset and mode
checks above remain the reproducible Stage-05 review procedure.
