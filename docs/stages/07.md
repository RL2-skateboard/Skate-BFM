# Stage 07

Status: WAITING_REVIEW. Isaac Sim is excluded by project scope.

The mjlab backend now constructs board, contact, robot and rider scenes through
the installed `mjlab.sim.Simulation` on CUDA. The simulation owns the physics;
the native MuJoCo data object is only a viewer mirror. `num_envs` and
`view_env` select batched GPU state, and partial reset preserves the other
environments' state within the Warp forward tolerance.

Verified on the target machine with mjlab 1.6.0, MuJoCo 3.11.0, MuJoCo Warp
1.17.0 and CUDA device `cuda:0` (RTX 4060 Ti):

```bash
conda run -n skate-sim-mjlab python -m skate_sim check \
  --stage 07 --backend mjlab --num-envs 64
```

The check reports `physics_owner: mjlab.mujoco_warp`, device `cuda:0`, one
physics step, and partial reset validation. Board and contact scenes were
compiled and stepped; the official G1 rider scene also compiled and stepped
through MuJoCo Warp. Policy/action-history parity and a full batch rider policy
path remain pending because the existing official BFM adapter is still marked
`NotImplemented`.
